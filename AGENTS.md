# Engineering instructions

- At the start of a task, identify the concrete outcome, scope, expected behavior and acceptance check. If a missing detail could change an architecture decision, gameplay behavior or what counts as done, ask one concise, grouped question first. Ask before broad document searches or implementation; do not rummage through `Docs/` to guess what the user meant. If the task is already clear, proceed without a confirmation round.
- Work on technical implementation in the Unity project at `Unity Project [Idle build master]/IdleRPGBuildMaster/`. Treat `Docs/` as the source of truth for existing game design. Do not invent or silently change gameplay rules.
- Keep context small: one scoped task per chat; read only the documents relevant to it. If the task needs a design rule but names neither its behavior nor a source, ask for the missing information before exploring design documents. `Docs/README.md` is the design map; `Docs/Technical/00_Architecture_Requirements.md` defines architecture constraints; `Docs/Technical/01_Engineering_Handoff.md` is the short engineering baseline. Read the full architecture requirements for an architecture task, then use relevant sections in later implementation tasks.
- Keep simulation rules independent of scenes, GameObjects, animation timing and UI. Give account, run and encounter state explicit owners. Use stable IDs for saved content and controllable RNG/time where relevant.
- Search by path and topic, showing only relevant matches. Edit Unity source under `Assets/`, `Packages/` and `ProjectSettings/`; retain matching `.meta` files. Do not edit or inspect generated `Library/`, `Temp/`, `Obj/` or IDE project files unless a specific diagnostic requires it.
- For each implementation task, make the smallest complete change, run proportionate verification when tools are available, and report exact verification and any remaining blocker. Record durable technical decisions in the repository so future chats do not need the old transcript; include commit/working-tree state in the handoff.
